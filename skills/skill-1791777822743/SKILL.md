name: 视频深度长文（图文版）
description: >-
  Use when the user sends a YouTube/video link (or asks to 'digest' a video) and
  wants it rewritten as a full standalone Chinese deep-dive article with key

# 目标
把一条视频彻底消化，重写成一篇可以替代观看原视频的中文深度长文：读者不看视频，也能获得 90% 以上有价值的信息（观点、论证链、案例、数据、技术细节、人物判断、争议、预测）。详细 > 简短，完整 > 精炼，理解逻辑 > 简单总结。

# 1. 完整获取视频
- 用 yt-dlp `--dump-json` 取标题、简介、时长、频道、章节、描述栏信息；字幕优先人工字幕，其次自动字幕；都没有或被限流（429）时，下载音频用 faster-whisper 转写。
- 以完整字幕为主要依据，按上下文修正识别错误（尤其人名、公司名）。
- 无法完整读取时，明确说明能读到的范围和缺失部分；绝不根据标题编造。

# 2. 内部建立内容地图
拆解：为什么讨论、背景、核心判断、依据、概念、案例、数据、技术原理、方案比较、成功/失败案例、争议、限制条件、预测、建议；并标记哪些是事实、观点、推测、预测。先保证完整覆盖再成文。

# 3. 遗漏检查重点
- 所有重要观点（含第二、三层观点）。
- 论证链：背景 → 问题 → 原因 → 机制 → 案例 → 数据 → 推论 → 结论。
- 所有案例：说明是什么、为什么讲它。
- 重要数字尽量保留；未核实写“视频中提到……”。
- 人物/公司/机构/产品/论文/政策/事件，首次出现简述身份。
- 技术内容讲清逻辑：专业人士不觉浅，外行能看懂。

# 4. 深度编辑，不是逐字稿
删口头禅、重复、寒暄、串场、广告、闲聊；合并重复观点，但新数据/新案例/新条件/新结论必须保留。

# 5. 按逻辑重组（不按时间顺序）
标题（准确，不标题党）；导语（≤500 字：讨论什么、为何值得看、核心问题、本文回答什么）；一、问题如何产生；二、核心判断；三、变化的原因与机制；四、关键技术/商业/社会逻辑；五、重要案例（融入论点）；六、数据意味着什么；七、真正值得关注的结构性变化；八、争议、局限与反面观点；九、未来会发生什么（区分事实/观点/推测/预测）；十、启示；结语（回到核心问题，不重复全文）。小标题可按内容调整。

# 6. 写作风格
深度研究文章 + 高质量商业/科技长文（《财经》《财新》《晚点 LatePost》《第一财经》《经济观察报》、MIT Technology Review、The Economist、Bloomberg Businessweek 的感觉，不模仿具体措辞）。自然、清晰、信息密度高、专业不晦涩、有分析不堆料、有故事不过度文学化。避免 AI 腔，尤其少用：“值得注意的是”“不可忽视的是”“从某种意义上说”“在当今时代”“随着科技的发展”“这无疑是……”。

# 7. 篇幅
按信息量定：30 分钟约 5000～8000 字；60 分钟约 8000～15000 字；90 分钟以上 15000～25000 字或更长。标准是信息覆盖率 ≥90%。

# 8. 引用
转述为主、短句引用为辅；保留核心定义、标志性判断、有洞察的关键句。

# 9. 时间戳
重要观点、数据、案例、争议点标注【视频 mm:ss】。音频转写时注明时间戳以音频为准。

# 10. 关键图片与图表
- 视频中出现或引用的报告、论文、财报、PPT、数据图、产品图、架构图，原则上都配进文章。
- 来源优先级：① 原始出处（官方报告 PDF、论文、财报、官网、发布会幻灯片），用 pdftoppm 等按页渲染并裁到图表；② 拿不到再用 ffmpeg 截视频关键帧，逐张查看，只留清晰、相关的；③ 不得编造或改造图表，自制示意图须标“编者自制示意，非原图”。
- 选图：支撑核心论点、关键数据、对比和趋势的图；不要装饰性、模糊或重复的。一般 30 分钟视频 8～15 张。
- 每张图放在对应段落旁，编号 + 中文图注（展示什么、关键数字、出处如“《XX报告》第 15 页”或“视频截图【视频 12:30】”）；图中数据与视频说法不一致时指出。
- 文首注明图表版权归原作者/机构，仅摘录参考并注明出处。

# 11. 事实与观点分开
已知事实；视频中的事实陈述（“视频中提到……”“主讲人表示……”）；主讲人观点（“在主讲人看来……”“他的判断是……”）；预测（“他预计……”“视频给出的判断是……”）。主讲人转述他人报告时，区分报告原意与主讲人评论。

# 12. 外部核查
对关键事实适度联网核查；外部资料只用于解释和验证，不喧宾夺主；与视频矛盾时明确标注【外部核实】并说明差异，不偷偷改视频观点。

# 13. 输出四部分
1. 一句话讲清视频（100～200 字）。
2. 完整深度长文（含按第 10 条插入的图表）。
3. 核心知识清单：10～30 条，每条 1～3 句。
4. 视频内容覆盖检查：已覆盖议题、案例、数据、人物/公司/技术；已插入图表及来源（原始出处 vs 视频截图）和拿不到的图；无法确认的信息；字幕缺失或问题；不可访问部分；回答“没看视频的人仅读本文，能否理解 90% 以上重要信息？”——若否，继续补充后再交付。

# 交付
保存 Markdown（相对路径引用图片），并生成单文件自包含 HTML（图片 base64 内嵌、中文字体栈含 Noto Sans CJK / PingFang、响应式排版、带目录，如 `pandoc --embed-resources --standalone --toc`），用浏览器渲染截几屏 PNG 检查排版；同时保留带时间戳的文字稿。向用户发 HTML 文件，并简述核查出的差异。默认不再产出 PDF，除非用户另行要求。
